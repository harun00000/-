## 2. Задача и сохранённая модель

В сельской библиотеке каждая книга есть в одном экземпляре. Читатели приходят по расписанию, выбирают от одной до трёх книг и возвращают полученные книги через заданное число дней. На недоступные книги создаются заявки. После возврата библиотекарь уведомляет ожидающих и резервирует книгу одному из них.

Предметная модель, формат входных данных, стратегии FIFO/LIFO, request_rule, логирование и статистика сохранены из ИДЗ №1. Основное изменение ИДЗ №2 - переход от последовательной имитации к многопоточной.

**Входные параметры:** книги, читатели, дни посещений, желаемые книги, срок чтения, стратегия выбора заявки (`strategy`) и правило обработки желаемых книг и формирования заявок (`request_rule`). Период моделирования задаётся через `total_days` или `-d`; по умолчанию 13 дней.

**Основные инварианты:**

- У экземпляра книги не более одного владельца.
- Читатель не получает ту же книгу повторно до возврата.
- Выданная книга отсутствует в доступном фонде.
- Возвращённая книга свободна или зарезервирована одному ожидающему.
- Закрытая заявка не обслуживается повторно.

## 3. Многопоточность

Программа написана на C11 для Linux с использованием libc, pthread и POSIX semaphore. Каждый `Reader` работает в отдельном pthread, потому что у него есть собственное поведение и расписание посещений: в стандартном запуске их 3, максимум - 20. `Librarian` работает ещё в одном pthread и самостоятельно обрабатывает возвраты, уведомления и резервирование. `Book` и `Request` потоками не являются: это общие данные без самостоятельного поведения.

### Модельный день

`main` управляет условными днями внутри `simulation_run()`. Только главный поток меняет общий `current_day`, чтобы участники не могли независимо изменять модельное время. Реальное время и задержки не используются.

1. Главный поток через `sem_post(librarian_start)` разрешает библиотекарю начать возвраты. Библиотекарь выходит из `sem_wait`, обрабатывает возвраты, уведомления и резервы, затем сообщает об окончании через `phase_done`.
2. Дождавшись этого сигнала, главный поток разрешает посещения через отдельный `reader_start[idx]` каждого читателя. Поток читателя проверяет расписание, получает свои резервы и обрабатывает обычные желания.
3. Каждый читатель сообщает о завершении через `phase_done`, даже если сегодня не приходит. Главный поток ждёт всех читателей и только потом переходит к следующему дню.

Возвраты всегда выполняются до посещений: это сохраняет логику исходной модели и позволяет читателям работать с обновлённым состоянием библиотеки в тот же день. Порядок читателей внутри дня зависит от планировщика. При заявках в один день FIFO/LIFO учитывают фактический порядок их создания.

### Mutex и semaphore

**Mutex** защищает общие данные от одновременного изменения. Один `pthread_mutex_t` в `Simulation` защищает владельцев книг, резервы, заявки, книги на руках, списки желаний, текущий день, флаг завершения и статистику. Запись событий из потоков выполняется под тем же mutex.

Гонки двойной выдачи нет: проверка доступности и изменение владельца или резерва происходят внутри одной критической секции посещения. Другой читатель не может вклиниться между проверкой и выдачей.

**Semaphore** позволяет потокам ждать начала своей фазы и сообщать о завершении работы. `librarian_start` запускает возвраты, `reader_start[]` - посещения, `phase_done` передаёт подтверждения главному потоку. Во время `sem_wait` и `pthread_join` mutex не удерживается.

### Завершение

После последнего дня главный поток устанавливает `finished` под mutex и будит всех участников через их стартовые семафоры. Потоки проверяют флаг и выходят. Главный поток вызывает `pthread_join` для каждого созданного потока, затем `sem_destroy` и `pthread_mutex_destroy`.

После этого выводятся оставшиеся заявки, резервы и статистика, а `main` закрывает журнал. Ошибки создания потоков и объектов синхронизации проверяются; при частичном запуске завершаются уже созданные потоки и освобождаются созданные ресурсы.

## 4. Сборка и запуск

Нужны Linux, CMake и компилятор C11 с поддержкой pthread и POSIX semaphore. Команды выполняются из `hw-2`:

```bash
./run.sh
```

Или вручную:

```bash
cmake -S . -B build
cmake --build build
./build/library_sim
./build/library_sim -c config.txt -d 20 -r 5
```

Опции: `-d / --days` - количество дней, `-r / --reading-days` - срок чтения, `-c / --config` - файл конфигурации, `-h / --help` - справка. Значения CLI имеют приоритет над config. Формат входных данных показан в [config.txt](config.txt).

## Дополнительные возможности

- **Комментарии и Doxygen.** Логические блоки поясняются обычными комментариями, публичные структуры и функции описаны Doxygen-комментариями.
- **Работа с файловыми дескрипторами.** Логирование использует `open`, `write`, `close`.
- **Логирование.** Основные события и итоговая статистика сохраняются в `library.log`.
- **Тестовые наборы.** `test.sh` запускает 9 интеграционных сценариев с разными конфигурациями и без аргументов, ограничивая каждый запуск через `timeout 10s`.
- **Статистика.** В конце выводятся количество посещений, выдач, возвратов, созданных и выполненных заявок, уведомлений.
- **Config и CLI.** Исходные данные можно менять через config-файл и аргументы командной строки.
