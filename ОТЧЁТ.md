## 2. Условие задачи

В библиотеке есть заданное количество книг, каждая в одном экземпляре. Читатели приходят в библиотеку и выбирают от одной до трёх книг. Полученную книгу читатель хранит несколько дней, затем возвращает.

Если нужной книги нет в доступном фонде, читатель может взять остальные доступные книги и оставить заявку на неё. После возврата библиотекарь уведомляет ожидающих читателей. Если заявок несколько, получатель книги выбирается по заданной стратегии. Само уведомление не должно приводить к выдаче одного экземпляра нескольким читателям.

Нужно разработать консольное приложение для симуляции работы библиотеки. Библиотекарь и каждый читатель должны быть самостоятельными участниками модели.

**Входные параметры:** количество и список книг, количество читателей, график посещений, желаемые книги, срок чтения, правила создания заявок и уведомлений, стратегия выдачи возвращённой книги.

**Отображаемые события:** приход читателя, запрос книг, выдача, отсутствие книги, создание заявки, возврат, уведомление, повторный приход и получение ожидаемой книги.

**Инварианты:**

- Один экземпляр находится не более чем у одного читателя.
- Читатель не получает одну книгу повторно до её возврата.
- Выданная книга отсутствует в доступном фонде.
- Возвращённая книга либо доступна, либо назначена одному ожидающему.
- Закрытая заявка не обслуживается повторно.

**Завершение по условию:** после заданного числа посещений и возврата всех книг; после окончания периода симуляции с выводом невыполненных заявок; либо при прерывании пользователем, если есть режим без ограничения времени. В этой программе работа заканчивается после заданного периода симуляции.

## 3. Реализация

Программа написана на C11. Для книг и читателей используются обычные массивы: максимум 15 книг и 20 читателей. Входные данные проверяются до заполнения структуры симуляции.

Основные объекты:

| Сущность | Назначение |
|---|---|
| `Book` | Айди и название книги. |
| `Reader` | Айди, имя, желаемые книги, книги на руках, дни возврата и посещений. |
| `Librarian` | Айди и имя библиотекаря. Функция `librarian_notify()` уведомляет читателя о возврате книги. |
| `Request` | Заявка на книгу: айди книги и читателя, день создания и признак активности. |
| `Simulation` | Общее состояние: участники, книги, заявки, владельцы, резервы, срок чтения и статистика. |

## Сверка с условием

| Требование | Как выполнено |
|---|---|
| Книги в одном экземпляре | Для каждой книги хранится один текущий владелец |
| Посещения читателей | Для каждого читателя задан список дней посещения |
| Выдача 1–3 желаемых книг | В `Reader` хранится список желаемых книг |
| Заявка на занятую книгу | Создаётся активный `Request` |
| Уведомление после возврата | Библиотекарь уведомляет всех ожидающих |
| Выбор при нескольких заявках | Используется FIFO или LIFO |
| Нет двойной выдачи | Перед выдачей проверяется владелец и резерв |
| Завершение по периоду | После последнего дня выводятся оставшиеся заявки и резервы |

Симуляция идёт по условным дням. В начале каждого дня программа обрабатывает возвраты. День возврата равен дню выдачи плюс срок чтения. Для возврата не нужно отдельное посещение по расписанию.

После возврата книги библиотекарь уведомляет всех читателей с активными заявками на неё. Затем функция работы с заявками выбирает одну из них: FIFO - самую раннюю активную заявку, LIFO - самую позднюю. В config-файле стратегия задаётся параметром strategy. По умолчанию используется FIFO. Если день создания совпадает, для FIFO выбирается более ранняя запись, для LIFO - более поздняя.

Выбранная заявка закрывается, а книга резервируется только за одним читателем. Остальные заявки остаются активными. Уведомление само по себе не выдаёт книгу и не меняет заявки. Получить книгу по резерву можно только при посещении в более поздний день.

После возвратов программа смотрит, кто должен прийти в библиотеку в этот день. Сначала читатель получает книги по своим резервам, затем программа проверяет остальные желаемые книги. Доступная книга выдаётся. Если книга занята или зарезервирована, создаётся заявка, если такой активной заявки ещё нет. Полученная книга удаляется из списка желаемых.

Для соблюдения основных инвариантов используются такие проверки:

- **Один экземпляр - один владелец.** Перед выдачей проверяется `owner_ids`. Если книга уже у кого-то, выдать её нельзя. Книгу по резерву может получить только указанный в нём читатель.
- **Нет повторной выдачи до возврата.** `reader_has_book()` проверяет, есть ли книга у читателя. Ещё одна проверка выполняется в `reader_add_book()`.
- **Закрытая заявка не обслуживается повторно.** При поиске следующей заявки учитываются только записи с `is_active == true`. После выбора заявка становится неактивной.
- **Выданная книга отсутствует в доступном фонде.** После выдачи в `owner_ids` записывается айди читателя, поэтому такая книга считается занятой и другому читателю не выдаётся.
- **Возвращённая книга либо свободна, либо закреплена за одним ожидающим.** После возврата владелец сбрасывается. Если есть заявки, программа выбирает только одну из них по FIFO/LIFO и создаёт один резерв. Если заявок нет, книга остаётся свободной.

В конце отдельно выводятся активные заявки и неполученные резервы. Это разные состояния: заявка закрывается при создании резерва, ещё до получения книги.

## 4. Интерфейс и запуск

Программа работает в консоли. Для сборки нужны Linux, CMake и компилятор с поддержкой C11. Команды выполняются из папки `hw-1`.

Запуск с автоматической сборкой:

```bash
./run.sh
```

Перед запуском собранной программы нужно выполнить:

```bash
cmake -S . -B build
cmake --build build
```

Поддерживаются следующие параметры:

| Опция | Значение |
|---|---|
| `-d`, `--days N` | Количество дней моделирования. |
| `-r`, `--reading-days N` | Срок чтения книги. |
| `-c`, `--config FILE` | Загрузка исходных данных из файла. |
| `-h`, `--help` | Вывод справки и завершение программы. |

Без параметров используются стандартные данные из `main.c`: две книги, три читателя, библиотекарь Никита Пичурин, срок чтения 3 дня и период симуляции 13 дней. Параметры `-d` и `-r` заменяют значения из config-файла независимо от порядка аргументов. При неверных аргументах программа выводит сообщение в `stderr` и завершается с ненулевым кодом.

Примеры запуска:

```bash
./build/library_sim -d 20 -r 5
./build/library_sim --config config.txt
./build/library_sim --config config.txt -d 30
```

Небольшой пример конфигурации:

```text
reading_days=3
total_days=13
strategy=fifo

book=1;Курочка ряба
reader=1;Даниил Подлягин;1;1,5
```

Стратегия выдачи задаётся параметром `strategy`: `fifo` выбирает самую раннюю заявку, `lifo` - самую позднюю. Если параметр не указан, используется FIFO.

Форматы записей:

```text
book=id;название
reader=id;имя;желаемые_книги;дни_посещений
```

Желаемые книги задаются через их айди, разделённые запятыми. Дни посещений тоже записываются через запятую. Например, `1,2` означает выбор двух книг. Загрузчик читает файл по строкам и пропускает пустые строки. Для чисел используется `strtol`. Также проверяется, что данные помещаются в массивы, айди не повторяются и желаемые книги существуют. Библиотекарь при загрузке файла остаётся стандартным.

## 5. Дополнительные возможности

- **Doxygen.** Структуры и публичные функции описаны в комментариях заголовочных файлов. Команда `doxygen Doxyfile` создаёт HTML-документацию в `docs/html`.
- **SOFT_ASSERT.** Макросы проверяют указатели, размеры и внутренние инварианты. Если проверка не проходит, выводится сообщение и функция завершает работу. Занятая книга или уже существующая заявка обрабатываются обычными условиями.
- **Конфигурационный файл.** Через него можно менять книги, читателей, расписания, длительность симуляции и стратегию выдачи возвращённой книги FIFO/LIFO без изменения кода.
- **Командная строка.** Опции разбираются в `main_utils.c` через `getopt_long`.
- **Интеграционные тесты.** `./test.sh` запускает четыре сценария: обычный, граничный с одной книгой и несколькими ожидающими, граничный с одним днём и проверку LIFO. Скрипт проверяет коды завершения, а для LIFO дополнительно проверяет сообщение о резерве за Виктором. Выводит `PASS`/`FAIL` и итог.
- **Логирование.** Основные события дополнительно записываются в лог-файл `library.log`. Для работы с ним используются файловый дескриптор и вызовы `open`, `write`, `close`. При новом запуске симуляции лог-файл очищается. Если его не удалось открыть, программа продолжает работу.
- **Статистика.** Считаются посещения, успешные выдачи и возвраты, созданные и выполненные заявки, уведомления. Итог выводится в терминал и лог-файл. Заявка считается выполненной, когда она закрывается при выборе читателя и создании резерва.

## 6. Результаты работы

Проект собран через CMake с флагами `-Wall -Wextra -Wpedantic`. Сборка прошла без предупреждений. Все четыре тестовых сценария успешно завершились.

Стандартный сценарий запущен командой:

```bash
./build/library_sim
```

Фрагмент реального вывода на четвёртый день:

```text
День 4: начало
  Возврат: Даниил Подлягин возвращает книгу «Курочка ряба».
Библиотекарь Никита Пичурин уведомляет читателя Никита Жилин: книга Курочка ряба возвращена
Библиотекарь Никита Пичурин уведомляет читателя Сергей Крылосов: книга Курочка ряба возвращена
Выбрана заявка №1 (день 2), читатель Никита Жилин. Заявка закрыта
Книга Курочка ряба зарезервирована за читателем Никита Жилин; владельца нет
Получение возможно при посещении в более поздний день
```

Оба читателя получили уведомления, но резерв получает только Никита Жилин: его заявка была создана первой. Сергей Крылосов пока не получает книгу, и его заявка остаётся в очереди.

При выборе `strategy=lifo` в такой же ситуации была бы выбрана самая поздняя активная заявка.

Программа выводит приход читателей, выдачу книг, создание заявок, возвраты, уведомления и резервирование. В конце выводятся оставшиеся заявки и резервы, сообщение о завершении и статистика.

Итог стандартного запуска:

```text
Невыполненных заявок нет

Библиотека В.С.Ё.
Статистика:
Приходов читателей: 8
Выдано книг: 4
Возвращено книг: 4
Создано заявок: 2
Выполнено заявок: 2
Отправлено уведомлений: 3
```

Уведомлений больше, чем выполненных заявок: при одном возврате уведомление могут получить сразу несколько читателей. При этом один экземпляр не выдаётся нескольким людям.

## Вывод

Создана консольная программа для симуляции работы сельской библиотеки по дням. Стратегии FIFO и LIFO вместе с резервированием позволяют выбирать одного получателя книги из ожидающих читателей. Одна книга не выдаётся нескольким людям одновременно. Config-файл, лог-файл, статистика и тесты позволяют запускать программу с разными данными и проверять её работу.
