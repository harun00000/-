# ИДЗ №2 - Сельская библиотека

Многопоточная версия ИДЗ №1 на C11, вариант 18. [Отчёт](ОТЧЁТ.md) · [Условие](i-tasks.pdf#page=37).

## Что изменилось

- Каждый читатель - отдельный pthread.
- Библиотекарь - отдельный pthread.
- Mutex защищает общее состояние библиотеки.
- Semaphore синхронизирует этапы модельного дня.
- Предметная логика, логирование и статистика ИДЗ №1 сохранены.

## Сборка и запуск

Нужны Linux, CMake и компилятор C11 с поддержкой pthread и POSIX semaphore. Команды выполняются из `hw-2`.

```bash
./run.sh
```

Или вручную:

```bash
cmake -S . -B build
cmake --build build
./build/library_sim
```

## Параметры

- `-d / --days N` - количество модельных дней.
- `-r / --reading-days N` - срок чтения книги.
- `-c / --config FILE` - файл конфигурации.
- `-h / --help` - справка.

Config поддерживает `reading_days`, `strategy=fifo/lifo`, `request_rule=on_unavailable/always_wait`, записи `book` и `reader`, необязательный `total_days` (по умолчанию 13). Пример - [config.txt](config.txt). Параметры CLI имеют приоритет.

FIFO выбирает раннюю заявку, LIFO - позднюю; `on_unavailable` разрешает брать доступные книги, `always_wait` откладывает обычные выдачи при наличии недоступной желаемой книги. Свои резервы обрабатываются первыми.

```bash
./build/library_sim -c config.txt -d 20 -r 5
```

## Тесты

После сборки:

```bash
./test.sh
```

9 сценариев: обычный, одна книга, один день, LIFO, FIFO, `always_wait`, `on_unavailable`, 20 читателей и запуск без аргументов. Проверки используют Bash, `grep` и обычные shell-утилиты; каждый запуск ограничен `timeout 10s`. Итог: `Tests passed: 9/9`.

## Многопоточность

Потоки `Reader` обрабатывают посещения, поток `Librarian` - возвраты. Mutex защищает общие данные, семафоры задают порядок фаз: возвраты → посещения → следующий день. Главный поток управляет условными днями, ждёт окончания фаз и при завершении вызывает `pthread_join` для всех участников.
