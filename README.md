# Сельская библиотека

Консольная симуляция на C11, вариант 18. Читатели выбирают от одной до трёх книг, берут доступные экземпляры и оставляют заявки на занятые. После возврата библиотекарь уведомляет ожидающих, а книга резервируется одному читателю по выбранной стратегии.

Поддерживается:

- Моделирование по дням: посещения, выдачи, возвраты, заявки и резервы.
- Стратегии FIFO и LIFO; по умолчанию FIFO.
- Конфигурационный файл и параметры командной строки.
- Журнал `library.log`, итоговая статистика и вывод оставшихся заявок и резервов.
- Интеграционные тесты (`test.sh`), проверки `SOFT_ASSERT` и документация Doxygen.

## Быстрый запуск

Для запуска нужны Linux, CMake и компилятор C с поддержкой C11.

```bash
chmod +x run.sh
./run.sh
```

Скрипт сам собирает проект и запускает стандартный сценарий.

Для запуска интеграционных тестов:

```bash
bash ./test.sh
```

Проверяются пять сценариев: обычный, с одной книгой, с одним днём, стратегия LIFO и правило always_wait. Ожидаемый итог: `Tests passed: 5/5`.

Перед запуском с опциями соберите проект через CMake:

```bash
cmake -S . -B build
cmake --build build
```

```text
Использование:
  ./build/library_sim [опции]

Опции:
  -d, --days N          количество дней моделирования
  -r, --reading-days N  срок чтения книги
  -c, --config FILE     загрузить данные из файла
  -h, --help            показать справку
```

## Примеры запуска с параметрами

```bash
./build/library_sim -d 20 -r 5
```

```bash
./build/library_sim --config config.txt
```

## Формат конфигурационного файла

Пример `config.txt`:

```text
reading_days=3
strategy=fifo
request_rule=on_unavailable

book=1;Курочка ряба
book=2;Убийство в Реутовском экспрессе. 2026г.

reader=1;Даниил Подлягин;1,2;1,5
reader=2;Никита Жилин;1;2,3,6
reader=3;Сергей Крылосов;1;2,4,10
```

`reading_days` задаёт срок чтения книги. Дополнительно можно задать `total_days` - длительность периода симуляции. Если параметр не указан, используется 13 дней. По окончании периода программа выводит оставшиеся заявки и резервы и завершает работу. Опция `-d` / `--days` меняет длительность симуляции и имеет приоритет над config-файлом.

Стратегия выдачи: `strategy=fifo` — самая ранняя заявка, `strategy=lifo` — самая поздняя. Если строка отсутствует, используется FIFO.

Правило формирования заявок:

- `request_rule=on_unavailable`: доступные книги выдаются сразу, на недоступные создаются заявки.
- `request_rule=always_wait`: если есть недоступная желаемая книга, остальные обычные желаемые книги в этот приход не выдаются и остаются в списке желаний; заявки создаются только на недоступные книги.

Если параметр отсутствует, используется `on_unavailable`. Книги по ранее оформленным резервам выдаются в начале посещения при обоих правилах.

Формат читателя:

```text
reader=id;имя;желаемые_книги;дни_посещений
```
